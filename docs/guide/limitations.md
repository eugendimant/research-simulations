# What this tool does and does not do

This page is the plain version of the feature list. Read it before you rely on a simulated dataset for anything beyond testing.

## What it is for

- Testing a survey and an analysis pipeline before real data exist: variable coding, reverse scoring, exclusions, scripts, pre-registered analysis code.
- Teaching: practicing data cleaning and analysis on a dataset whose design is known.
- Rough planning: seeing what a dataset with a given design, sample size and assumed effect looks like.

## What it is not

- **It is not data about real people.** Every number comes from rules and parameters written into the program. The parameters are informed by published research on survey behavior (response styles, satisficing, reverse-item failure, effect-size ranges), but the output is a model of that research, not an observation.
- **It has not been validated against a real-data benchmark.** Checks so far are internal: reproducibility under a seed, scale ranges, recovery of the effect you ask for, and structural checks over a library of Qualtrics files. No claim is made that a simulated dataset is statistically indistinguishable from data collected from a real panel.
- **It is not a power-analysis tool.** You can read off the simulated effect at your N, but one simulated run is one random draw. Use a proper power calculation, or repeat runs with different seeds.
- **It must not be passed off as real data.** Reporting simulated data as collected data is research misconduct. Label simulated datasets as simulated everywhere they travel (the `SIMULATION_MODE` column in `Simulation_Diagnostics.csv` and `Metadata.json` are there for that reason).

## Design coverage

| Supported | Not modeled |
|---|---|
| Between-subjects conditions and factorial crossings read from the Qualtrics randomizer or built by hand | Within-subject and repeated-measures designs: each simulated person sees one condition, and the design step warns you when you pick another design |
| Likert, matrix, slider, numeric-input, constant-sum, rank-order and similar scale types | Clustered or multilevel data (classrooms, sites, teams) |
| Several DVs with a correlation structure between them | Longitudinal change over time |
| Mediator and moderator variables with a specified correlation pattern | Survey branching: display logic and skip logic in the QSF do not reach generation |

Two detection limits are worth knowing. Reverse-keyed items and named instruments are **not** detected from a QSF, so mark reverse-keyed items on the Design page or describe them to the study builder. A scale detected from a QSF can also be mislabeled, so review the detected scales and conditions before generating.

## How effects behave

- **Effects you specify** are calibrated to the scale you are measuring: a `d` of 0.5 on a multi-item scale gives an observed standardized difference near 0.5 on the scale mean. The match is approximate. Expect run-to-run variation from sampling (about ±0.15 in d at 100 per group) and smaller shifts from noise settings and rounding to scale points.
- **Inferred effects** are a heuristic. Where you specify nothing, the tool reads the condition names (for example gain vs loss, or a named paradigm with a published estimate) and builds in a small difference so that conditions are not identical. They are not calibrated to a target `d`. Switch them off in Advanced Settings for a true null.
- **Economic-game outcomes** (dictator, trust, ultimatum, public goods and similar) are generated by a behavioral-economics model, which replaces the numeric generator's values for those columns. A `d` you specify on such an outcome is restored after the model runs, so the observed d is slightly below the request when answers pile up at the scale limits.
- **Scales with reverse-keyed items** show a smaller observed d on the scale mean than the request, because the simulator includes respondents who ignore item direction (as real samples do).
- Every run records the effects that were built in and the effects observed in `Metadata.json` (`effect_sizes_applied`, `effect_sizes_observed`).

More detail: [How effects work](how-effects-work.md).

## Open-ended text

- **Built-in AI** (free): text for the first 100 participants is written by free language-model providers. Participants beyond 100 receive text from the built-in template engine. Numeric data are generated for every participant either way. The `_Generation_Source` column in `Simulation_Diagnostics.csv` says which source wrote each response.
- **Template engine**: unlimited, offline and reproducible under a seed, but more repetitive than AI text.
- **Your own API key**: lifts the free-tier cap and uses your own provider quota.
- AI text varies between runs even under a seed, because provider output is not deterministic. Numeric data are reproducible; AI-written text is not.
- Text is written to fit each participant's ratings and the question topic. It is suitable for testing text-processing code. It is not suitable for training or evaluating models that must tell human text from machine text.
- Numeric text boxes (age, year of birth, counts, percentages, amounts) are answered with numbers, not prose, and a text box that repeats a numeric question already in the data is skipped.

## Privacy

- You upload a survey file (questions and flow), never participant data. The simulated participants are not real people.
- Sharing the survey file with the tool's researchers is optional and off by default: a checkbox on the upload step applies to one file. Generated data and designs built in the study builder are never shared.
- Do not upload a survey that contains confidential stimulus material you are not allowed to share.

## Reproducibility

- Set a seed on the Generate step to regenerate the same numeric dataset from the same design and settings. The seed of every run is in `Metadata.json` and in the `SIMULATION_SEED` column of `Simulation_Diagnostics.csv`.
- The same seed with a different software version can give a different dataset, because the generator changes between versions. `Metadata.json` records the version.

## Size limits

Template-engine runs go up to 10,000 participants. With the built-in AI, text comes from the AI for the first 100 participants only.
